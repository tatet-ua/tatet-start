# Дашборд `stats.<домен>` — разведка, состав, выкладка, приёмка

## 1. Разведка

Два разведчика (`scout` набора) параллельно, только чтение, результат файлом в проект дашборда.

**Образец.** Репозиторий дашборда-образца даёт ментор. Что выписать:
- стек и устройство папок; build pack и Dockerfile; как схема базы попадает в базу при старте контейнера;
- переменные окружения — только имена;
- задачи сбора: имена, расписание, что пишут в базу; журнал прогонов и кнопка ручного запуска;
- экраны и что каждый читает; как устроен вход (Tatet Auth, роли) и кто правит настройки;
- MCP-сервер, если есть: инструменты и как он проверяет доступ;
- как экраны ведут себя без данных (обычно никак: образец не жил на пустой базе — см. ловушку в SKILL.md).

**Сайт студента.** Что выписать:
- какие свои данные у сайта есть (заявки, заказы, регистрации, каталог) и где они лежат;
- какие действия посетителей важны студенту и какие из них стоит отправлять в GA4 событиями;
- языки сайта, страны аудитории — от этого зависят срезы и язык дашборда.

## 2. Вопросы студенту — по одному

Один вопрос за ход, рекомендуемый вариант первым с пометкой «(рекомендую)». Следующий вопрос — после ответа:
ответ на первый часто снимает остальные.

1. **Состав первой версии.** Рекомендация: «Обзор» (визиты, пользователи, источники, тренд за 30 дней), «Поиск»
   (клики, показы, запросы и страницы из Search Console), «Журнал сбора». Остальное — второй версией по факту.
2. **Язык интерфейса.** Рекомендация: язык, на котором студент работает; второй язык — только если дашборд будет
   смотреть кто-то ещё.
3. **MCP-сервер для агента.** Рекомендация: не в первой версии, если студент не собирается спрашивать агента о
   статистике; да — если собирается (по образцу, только чтение).

## 3. Спека и план

Короткая спека в `AGENTS.md` проекта дашборда: для кого, экраны, источники и квоты (GA4 Data API, Search Console API,
задержки данных), расписание сбора, кто входит, что не делаем. План по этапам. Код — после «ок» студента.

## 4. Обязательное в первой версии

- **Экраны читают базу**, во внешние API наживо не ходят. Сбор — задачи `ga:pull` и `gsc:pull` по расписанию
  (раз в сутки утром по часовому поясу студента), каждая пишет прогон в журнал: время, `ok`, сколько строк, текст
  ошибки.
- **Кнопка ручного запуска** у каждой задачи на странице журнала; повторный запуск, пока идёт прогон, — отказ.
- **Зрелость данных.** GA4 дописывает последние 2–3 дня задним числом: снимок дня перезаписывается, пока ему меньше
  72 часов, и помечается как неполный. Search Console отдаёт данные с задержкой 2–3 дня — «нет данных за вчера» не
  ошибка.
- **Пустое состояние** на каждом экране: «Данных ещё нет — первый сбор …», а не 500 и не пустая таблица.
  Ответ API без данных (`{ empty: true }` и подобное) экран обязан проверять до чтения полей.
- **`/health`** без входа: `SELECT 1` в базу и время последнего прогона каждой задачи.
- Ключи Google — из переменных сайта (или со страницы `/settings`, запасной путь), в лог не печатаются.

## 5. Выкладка через хостинг менторства

Порядок вызовов MCP:
1. `site_create` — сайт `stats` из репозитория дашборда (закрытый репозиторий — с deploy key, как подскажет ответ
   инструмента). Адрес на хостинге — `stats-<студент>.tatet.app`.
2. `db_create` (одна база на аккаунт), `site_db_attach` — сайт получает `DATABASE_URL`.
3. Переменные: несекретные — `site_env_set`; ключ Google — скриптом, см. `google-api.md`, раздел «Секреты в
   переменные сайта»; секрет подписи сессий — `site_env_generate`.
4. `site_auth_enable` — клиент входа Tatet Auth для сайта; подключение в коде — по ответу инструмента (PKCE, без
   секрета). `site_auth_grant` — почта студента и почта ментора. `site_auth_users` — оба в списке.
5. `site_deploy`, затем `site_status` и `site_logs` до статуса «работает».

Лимиты хостинга: 5 сайтов на аккаунт, 256 МБ памяти и 0,5 CPU на сайт, не больше 10 выкладок в час. docker-compose,
диски и свои сети запрещены — дашборд должен жить одним контейнером с базой аккаунта.

**Свой домен `stats.<домен>`.** Студент в своём Cloudflare: запись `A`, имя `stats`, значение — IP сервера
аккаунта (его покажет ментор или карточка домена), проксирование выключено (серое облако). Подключает домен
ментор в карточке аккаунта на хостинге; карточка сама проверит DNS, выпустит сертификат и добавит адрес входа
клиенту Tatet Auth. Статусы: «ожидает DNS» → «выпускается сертификат» → «работает». Причина в статусе
(«указывает не туда», «включено проксирование Cloudflare») — исправить запись, ментор жмёт «проверить сейчас».

## 6. Первая сборка данных

На странице журнала запустить `ga:pull`, затем `gsc:pull`. Проверка — по строке «последний прогон» на странице, а не
по сообщению в чате: кнопка ответа агенту в чате и кнопка запуска на странице — разные вещи. Оба прогона `ok`;
нули в GA4 до установки счётчика и пустой Search Console в первые дни — норма.

## 7. Приёмка

Проверяющий с чистым контекстом (`verifier` набора): кода не видел, на проде только читает (GET и HEAD).
Каждая строка — команда и что должно получиться.

| Что | Команда | Ожидание |
|---|---|---|
| страницы без входа | `curl -sI https://stats.<домен>/` и каждый экран | 302 на вход Tatet Auth |
| API без входа | `curl -s -o /dev/null -w "%{http_code}" https://stats.<домен>/api/<путь>` по каждому | 401 |
| обходы путей | `/api/../api/<путь>`, `/API/<путь>`, `/api/<путь>/`, `%2e%2e`, двойной слеш | 401 или 400, не 200 |
| запуск задачи без входа | `curl -s -X POST .../api/tasks/ga:pull/run` | 401, задача не стартовала |
| здоровье | `curl -s https://stats.<домен>/health` | 200, база `ok`, прогоны задач видны, ключей нет |
| OAuth | `/auth/start` | 302 на `auth.tatet.net` с `code_challenge` и `redirect_uri` на `https://stats.<домен>/...` |
| чужой пользователь | вход учёткой без доступа к клиенту | отказ на стороне Tatet Auth |
| MCP (если есть) | запрос без токена и с чужим токеном | 401 |
| адрес хостинга | `curl -sI https://stats-<студент>.tatet.app/` | ведёт себя так же, как основной домен |
| порт базы | `Test-NetConnection <IP сервера> -Port 5432` (или `nc -zv`) | соединение не устанавливается |
| ключи в ответах | grep ответов `/health` и страниц на `PRIVATE KEY`, `iam.gserviceaccount.com` | пусто |

Итог проверяющий отдаёт таблицей «проверка · ожидание · факт». Принимает ментор.
