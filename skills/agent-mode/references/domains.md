# Відповідності за областями — чотири питання рамки

Довідник до розділу 0 скіла `agent-mode`. Рамка одна, відповіді на чотири питання збирання різні в кожній
області. Таблиця дає приклади, не вичерпний перелік: якщо об'єкт роботи власника не схожий на жоден стовпець,
відповіді складаються за тим самим принципом.

## Чотири питання × чотири області

| Питання | Розробка | Контент і SEO | Ігри | Інше / офісна робота |
|---|---|---|---|---|
| **1. Об'єкт роботи** — що править виконавець, за межі чого він не виходить | файли коду за списком, міграція, конфіг; не тести без дозволу | стаття або розділ, метаописи сторінок, таблиця перелінковки, план публікацій; не чужі статті | сцена або рівень, таблиця балансу, скрипт механіки, набір ресурсів (спрайти, звуки); не файли імпорту рушія | документ, таблиця розрахунку, презентація, чернетка листа, перелік задач; не вихідні дані клієнта |
| **2. Джерело правди** — що читає розвідник до роботи | код оригіналу або референсу, інструкція проєкту, постановка, схема бази | бриф, пошукова видача за запитами, правила площадки, семантичне ядро, стиль-гайд | дизайн-документ, таблиця балансу, референсні ігри, обмеження рушія і платформи | регламент або шаблон, попередні версії документа, вихідні дані (виписки, листування), вимоги замовника |
| **3. Перевірка з наперед записаним очікуванням** — що виконує перевіряльник | команда і вивід: тести з нулем падінь, збірка з кодом 0, `curl` з очікуваним статусом і тілом | чекліст фактів з джерелами; замір до/після: обсяг, частотність ключів, число внутрішніх посилань, оцінка читабельності; прогін сторінки після публікації | прогін сценарію: рівень проходиться від старту до фінішу за N хвилин, усі предмети доступні; замір балансу: частка перемог у симуляції в межах; збірка запускається | чекліст: усі розділи шаблону заповнені, числа збігаються з джерелом; звірка підсумків таблиці з вихідними; відкриття файлу в цільовій програмі без помилок |
| **4. Незворотне** — тільки оркестратор після «ок» власника | деплой, злиття в головну гілку, `git push`, міграція бази, видалення даних, правка доменів | публікація на сайті, відправлення в розсилку, оплата розміщення, видалення старих сторінок, зміна адрес сторінок | реліз у магазин, оновлення збірки для гравців, видалення збережень, покупка ресурсів | відправлення листа або документа адресату, оплата, підпис, видалення файлів, зміна спільної таблиці |

Що є «спільним ресурсом», який агенти ділять послідовно (розділ 3 скіла): у розробці — порт, база, графічний
процесор; у контенті — обліковий запис площадки, ліміт зовнішнього сервісу перевірки; в іграх — рушій з одним
відкритим проєктом, пристрій для тестів; в офісній роботі — спільний документ, вікно на екрані власника.

## Приклади середини — по чотири-п'ять етапів

Краї однакові скрізь: розвідник на вході, перевіряльник на виході. Нижче — лише середина. Виконавці на одному етапі
можуть іти паралельно, якщо їх об'єкти не перетинаються.

### Розробка: нова частина застосунку

1. Розвідка (`scout`, 1–3 екземпляри): як зроблено в оригіналі, що зачепить правка, які тести є.
2. План нарізки — оркестратор: частини без перетину файлів, у кожної перевірочна команда.
3. Виконавці по частинах (середня або старша модель), паралельно тільки у worktree.
4. Перевіряльник після кожного (`verifier`): команди з очікуваним виводом; оркестратор читає зміни.
5. Рев'юер правил (`rules-reviewer`) перед «готово»; викладає оркестратор після «ок».

### Контент і SEO: стаття під пошуковий запит

1. Розвідка (`scout`, по одному на запит): видача, конкуренти, факти з джерелами — таблиця «питання · відповідь ·
   джерело».
2. Кластеризація і структура (старша модель): теми, порядок розділів, ключі по розділах — файл-план.
3. Чернетка (виконавець, середня модель): тільки файл статті, факти лише з таблиці розвідки.
4. Вичищення ознак машинного тексту і перелінковка (виконавець, окремий список: стаття + таблиця посилань).
5. Перевіряльник: чекліст фактів із джерелами, замір обсягу і ключів до/після; публікує оркестратор після «ок».

### Ігри: новий рівень

1. Розвідка (`scout`): дизайн-документ, обмеження рушія, як зроблені сусідні рівні, таблиця балансу.
2. Концепт рівня (старша модель): схема, перелік подій, цільовий час проходження — файл-концепт.
3. Чернетка сцени (виконавець): тільки файли сцени і ресурси зі списку; файли імпорту рушія не чіпати.
4. Розрахунок балансу (старша модель, читання): симуляція або таблиця, частка перемог у межах — число до/після.
5. Тестовий прогін (`verifier` або спеціальна роль «тестувальник рівня»): сценарій проходження від старту до фінішу,
   результат кожного кроку записано; збірку для гравців оновлює оркестратор після «ок».

### Інше / офісна робота: звіт для замовника

1. Розвідка (`scout`): регламент або шаблон, попередні версії, вихідні дані — що є, чого бракує.
2. Зведена таблиця (виконавець, середня модель): тільки файл таблиці, кожне число з посиланням на джерело.
3. Чернетка документа (виконавець, старша модель): тільки файл документа, числа лише з таблиці.
4. Перевіряльник: чекліст розділів шаблону, звірка кожного числа з джерелом, відкриття файлу без помилок.
5. Надсилає адресату оркестратор після «ок» власника.

## Типові помилки збирання

| Помилка | Чому це погано | Як правильно |
|---|---|---|
| Десятки агентів на механіку: по агенту на кожну сторінку, щоб витягти заголовок | дорого і повільно, судження там не потрібне | один виконавець пише і запускає скрипт, результат у файли; агенти йдуть по файлах лише там, де потрібне розуміння |
| Перевірка автором: виконавець сам «перевірив і все працює» | автор у тому самому контексті не звіряє результат із критерієм, він його переказує | перевіряльник із чистим контекстом, звіт автора не читає, критерій з початкової задачі |
| Агент з правом запису «про всяк випадок»: розвідник зі `Write`, аудитор з `Bash` | рано чи пізно «допоможе» і щось поправить; одна галюцинація — і зміна в об'єктах, яких у задачі не було | читачів запускати через типи набору без інструментів запису; виконавцю — явний список об'єктів |
| Краї пропущені: «задача ясна, розвідка не потрібна», «виконавець надійний, перевірка зайва» | без входу робота будується наосліп, без виходу «готово» лишається словом автора | краї не обговорюються ні для якої області; розвідка може бути короткою, перевірка — ні |
| Незворотне віддане агенту: «опублікуй, якщо все добре» | агент не бачить розмови з власником і не має «ок» | незворотне робить тільки оркестратор, одна дія за раз, показавши параметри |
| Модель не вказана | агент успадковує найдорожчу модель оркестратора на механічну роботу | `model` у кожному запуску, вибір за ціною помилки |
| Критерій перевірки записаний після роботи | критерій підганяється під результат | очікування записується в промпт до запуску виконавця |

## Словничок — технічні слова скіла для власника, який не пише код

Слова з розробки в скілі лишаються, бо так їх побачить агент і так вони звучать у Claude Code; тут — що це означає
і чим воно є поза кодом. Якщо проєкт не в git і без командного рядка, відповідний пункт правила виконується
еквівалентом з правого стовпця.

| Слово | Що це | Еквівалент поза кодом |
|---|---|---|
| Деплой | викладання нової версії застосунку на сервер, щоб її побачили користувачі | публікація статті, оновлення збірки гри в магазині, відправлення документа адресату |
| Git | система збереження версій файлів: пам'ятає кожну зміну, ким і коли зроблену | папка з пронумерованими версіями документа; «історія версій» у хмарному офісі |
| Коміт | збережена в git порція змін з описом | «зберегти як нову версію» |
| Гілка, злиття | окрема лінія змін і її повернення в основну | чернетка, яку потім вливають в основний документ |
| `git push` | відправлення збережених змін на спільний сервер | виклав чернетку в спільну папку команди |
| `git status --short` | перелік файлів, змінених від останнього збереження | список файлів, у яких змінилася дата зміни |
| `git diff` (дифф) | перелік змін рядок за рядком між двома версіями | порівняння документів «показати зміни» |
| `stash`, `checkout`, `reset`, `clean` | команди git, що відкочують або ховають зміни в робочій папці; агентам заборонені | «повернути попередню версію» для всіх файлів одразу — ламає роботу сусідів |
| Worktree | друга робоча папка того самого проєкту зі спільною історією, для паралельної роботи | копія папки проєкту для другої людини, з подальшим зведенням |
| `grep` (`grep -c`) | пошук тексту по файлах з командного рядка; `-c` — скільки разів знайдено | «знайти в усіх файлах» з числом збігів |
| `curl` GET / HEAD | прочитати сторінку або її заголовки командою, нічого на ній не натискаючи | відкрити сторінку і подивитися, що вона відповідає, без входу і форм |
| Хук | скрипт, який Claude Code запускає сам у відповідь на подію (завершення агента, виклик інструмента) | автоматичне правило «коли сталося X — зроби Y» |
| Код повернення 0 | команда завершилася без помилки; будь-яке інше число — помилка | «збережено без помилок» у програмі |
| PATH | список папок, де система шукає програми за ім'ям | якщо програма «не знайдена», її папки немає в цьому списку |
| MCP | спосіб підключити до Claude Code зовнішні інструменти (дошку, браузер, сервіс) | «розширення» або «плагін» у звичній програмі |
| Lock-файли | записи точних версій залежностей проєкту, створюються автоматично | службові файли, які не правлять руками |
| Токени | одиниці тексту, якими рахується обсяг і вартість роботи моделі | «знаків» у тексті: більше прочитано і написано — дорожче |
| Збірка | перетворення вихідних файлів на те, що запускається або публікується | експорт відео, збирання PDF з макета, експорт гри з рушія |
| Scratchpad | папка тимчасових файлів сесії, куди агенти пишуть звіти | робоча папка «чернетки», яку не шкода прибрати |
