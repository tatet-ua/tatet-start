# stats-dashboard

Разведка, состав первой версии, выкладка, ключ Google на сайт и приёмка — [references/dashboard.md](references/dashboard.md).

## Всегда

- **Стоп** означает: дождаться, пока студент или ментор сделает действие сам или скажет «да» в чате.
- В Cloudflare студента не входить: записи DNS вносит он, агент даёт точные значения и проверяет.
- Ключи — только через скрипты и `with-env.py` набора; значения не печатать.
- Push и выкладка — после «ок» студента.

## Перед началом

1. `../site-analytics/scripts/check_google.py <папка аналитики>/.env` (путь от папки этого скила) → две строки `OK`. Нет — сначала
   `site-analytics`, шаги 1–3.
2. MCP хостинга менторства: `me` отвечает аккаунтом студента. Нет — **стоп**, нужна ссылка от ментора.

## 1. Разведка и спека

1. Разведка, только чтение: образец, который назовёт ментор, и свои данные сайта студента.
2. Вопросы студенту по одному, с рекомендацией: экраны первой версии, язык, нужен ли MCP.
3. Спека и план в `<папка аналитики>`. **Стоп:** код после «ок».

## 2. Код

По этапам, после каждого — `verifier` набора. Каждый экран на пустой базе показывает пустое состояние, не ошибку:
GA4 отдаёт первый день наутро, Search Console — через 2–3 дня. Перед выкладкой `build` зелёный: Prisma и Nuxt
ломаются только на настоящей сборке.

## 3. Выкладка

1. Через MCP хостинга — порядок в справочнике. Ключ Google на сайт ставит `scripts/put_site_env.py`, не
   `site_env_set`.
2. **Стоп:** студент — `A stats` на IP сервера аккаунта, проксирование выключено (иначе нет сертификата); ментор —
   подключает `stats.<домен>` в карточке аккаунта.
3. Запустить `ga:pull` и `gsc:pull` кнопкой на странице журнала сбора.

Проверка: `curl -sI https://stats.<домен>/` → 302 на вход Tatet Auth; студент и ментор входят; оба прогона `ok`.

## 4. Приёмка

`verifier` набора по таблице «Приёмка» из справочника. **Стоп:** итог принимает ментор.
