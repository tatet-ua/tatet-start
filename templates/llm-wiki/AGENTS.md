# База знань — схема

Це інструкція для агента, який працює з цим репозиторієм. Claude Code читає її через `CLAUDE.md`,
Codex, Gemini CLI і Cursor — напряму. Схема коротка навмисно: усе, чого тут немає, вирішується за правилами нижче,
а не вигадується на місці.

## Ідея

Чат одноразовий, вікі накопичується. Ти й агенти кладете джерела в `raw/`, агент збирає з них
сторінки в `wiki/`. Джерела не редагуються ніколи, вікі завжди можна перезібрати з джерел.
Ритуал роботи: сесія починається з читання індексу й останнього логу, закінчується логом.

## Що де лежить

```
AGENTS.md            ця схема
CLAUDE.md            рядок-вказівник @AGENTS.md для Claude Code
index.md             хаб: один рядок на проєкт, сервіс, патерн; лише посилання, без абзаців
log.md               хронологія: один рядок на кожен ingest, що змінилося
raw/                 джерела, не редагуються
  sessions/          РРРР-ММ-ДД-<проєкт>.md   лог сесії агента (скіл session-end)
  specs/             <проєкт>-РРРР-ММ-ДД.md   специфікація проєкту або її версія на дату
  meetings/          листування, рішення від людей, транскрипти — як є
  docs/              документація сервісів, скриншоти, вивантаження, старі нотатки
wiki/                пише тільки агент через ingest
  projects/<проєкт>.md      що це, для кого, де живе, статус, джерела
  services/<сервіс>.md      адреса, навіщо, як підключити, документація
  decisions.md              рішення з датою, причиною і посиланням на джерело
  patterns/<тема>.md        граблі та прийоми, що трапилися щонайменше у двох проєктах
  infra.md                  сервери, домени, порти, де видають токени
boards/              дані дошки проєктів (команда board), сторінки шляху — у boards/progress/
```

Шлях до бази — змінна оточення `TATET_WIKI`, типово `<диск>:/project/llm-wiki`; її записує установник набору
tatet-start. Скіли беруть шлях звідти. Скіли й агенти живуть у плагіні tatet-start, не в цій папці.

## Правила

1. **Правка у `wiki/` без джерела в `raw/` заборонена.** Хочеш змінити факт — поклади файл із рішенням у
   `raw/meetings/` або скажи агентові в сесії, це потрапить у лог. Потім ingest.
2. **Кожне твердження у вікі посилається на джерело:** у кінці абзацу або рядка таблиці
   `[raw/sessions/2026-09-10-my-blog.md]`. Твердження без джерела — кандидат на видалення під час lint.
3. **`index.md` — рядки й посилання.** Формат рядка проєкту:
   `- [<ім'я>](wiki/projects/<ім'я>.md) — <одна фраза> · репо <посилання> · прод <адреса або «немає»> · статус <слово>`.
   Абзаци переїжджають у `wiki/projects/`.
4. **Патерн заводиться з другого разу.** Поки граблі трапилися в одному проєкті, вони живуть у
   `wiki/projects/<проєкт>.md`, розділ «Граблі». У другому проєкті — переїжджають у `wiki/patterns/` з посиланнями
   на обидва.
5. **Секретів ніде.** Лише імена змінних і місце, де їх видають; значення живуть у `$TATET_DEVOPS/.env`.
   Файл зі значенням у `raw/` не кладеться; якщо поклали — видалити з історії git і перевипустити ключ.
6. **Особисте не тут.** Стиль спілкування, звички, спостереження про людей — в авто-пам'яті агента на твоїй машині.
   Оцінки людей на ім'я не пишуться: замість «X зриває терміни» — «функцію Y не реалізовано».
   Фільтр перед записом: якщо завтра це прочитає колега, чи не відчує він, що підглянув особисте?
7. **Пам'ять проєкту не дублюється.** `AGENTS.md` у репозиторії проєкту описує, як із ним працювати; `CLAUDE.md` там —
   рядок-вказівник `@AGENTS.md` для Claude Code (рішення від 2026-09-20).
   `wiki/projects/<проєкт>.md` описує, що це і де живе, і посилається на репозиторій.
8. **Мова сторінок — українська**, цитати з джерел — як у джерелі. Терміни сервісів і код не перекладаються.
9. **Імена файлів** латиницею, через дефіси, дата попереду там, де вона є: `2026-09-10-my-blog.md`.

## Операції

### Початок сесії — скіл `/tatet-start:session-start`

1. Прочитати `index.md`.
2. Знайти в `raw/sessions/` останній файл по проєкту (за іменем), прочитати його цілком.
   Логу немає — відкрити `wiki/projects/<проєкт>.md`.
3. Першою відповіддю запропонувати: на чому зупинилися (одне-два речення), наступний крок, готовий текст запиту.

### Кінець сесії — скіл `/tatet-start:session-end`

Пише один файл у `raw/sessions/`: старт, хід, граблі, рішення, стан, беклог, готовий запит.
Файл створюється один раз і більше не правиться. Одразу після запису запускається ingest цього файлу,
потім оновлюється дошка проєкту.

### Ingest — скіл `/tatet-start:kb-ingest`

Вхід: один новий файл у `raw/`. Агент:
1. Читає файл цілком.
2. Знаходить сторінки `wiki/`, яких він стосується: проєкт, сервіси, рішення, патерни, інфраструктура.
3. Оновлює їх: нові факти додає з посиланням на джерело, застарілі замінює, суперечність
   лишає в тексті позначкою `⚠ суперечить [джерело]` — вирішує людина.
4. Оновлює рядок проєкту в `index.md` (статус, прод), заводить рядок, якщо проєкту не було.
5. Дописує рядок у `log.md`: `РРРР-ММ-ДД · <файл raw> → <які сторінки змінено>`.

Одне джерело може змінити десять сторінок. Ingest ніколи не править `raw/`.

### Lint — скіл `/tatet-start:kb-lint`

Раз на тиждень або перед передачею проєкту. Перевіряє серед іншого:
- суперечності між сторінками `wiki/`;
- файли в `raw/`, яких немає в `log.md` (не проковтнуті);
- твердження без посилання на джерело;
- сторінки, на які ніхто не посилається, і посилання в нікуди;
- рядки `index.md`, чий статус старший за 60 днів без змін у `raw/`.

Повний перелік перевірок — у скілі. Результат — файл у `raw/sessions/` з датою і суфіксом `-lint`.
Виправлення йдуть через ingest цього файлу.

### Запит

Питання ставиться вікі, а не сирим файлам: `index.md` → сторінка → джерело, якщо потрібна точність.
Цінна відповідь, якої немає у вікі, кладеться в `raw/docs/` і проходить ingest.
